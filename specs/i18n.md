# Spec: i18n utilities

Covers `normalizeLocale`, `localeFromPathname`, and `getUiLabels` in `src/utils/i18n.ts`.

Tests: `tests/unit/i18n.test.ts`

---

## normalizeLocale(input?)

Normalizes an arbitrary string to a supported locale code (`'en'` or `'es'`).

### Behaviors

- Input starting with `'es'` (case-insensitive) returns `'es'`.
- All other inputs return `'en'` (the default).
- Empty string returns `'en'`.
- `undefined` returns `'en'`.
- BCP-47 tags like `'es-ES'` or `'es-MX'` return `'es'`.
- `'fr'`, `'de'`, `'zh'` all return `'en'`.
- `'EN'`, `'En'` return `'en'` (not a special match, falls through to default).

### Input

`input?: string` - any string or undefined

### Output

`LocaleCode` - either `'en'` or `'es'`

---

## localeFromPathname(pathname)

Extracts the locale from the first path segment of a URL pathname.

### Behaviors

- `/es/contact/` -> `'es'`
- `/en/contact/` -> `'en'`
- `/contact/` -> `'en'` (no recognized locale segment, defaults to en)
- `/es/` -> `'es'`
- `/` -> `'en'`
- The first non-empty segment is extracted by splitting on `/` and filtering empty strings.
- Delegates to `normalizeLocale` for the actual locale resolution.

### Input

`pathname: string` - a URL pathname (leading slash, optional trailing slash)

### Output

`LocaleCode` - either `'en'` or `'es'`

---

## getUiLabels(locale)

Returns the full set of UI strings for the given locale.

### Behaviors

- Returns English strings for `locale === 'en'` or any unrecognized locale.
- Returns Spanish strings for `locale === 'es'` (or `'es-ES'` etc. via `normalizeLocale`).
- All required `UiLabels` keys are present in both locales.
- No label value is an empty string.
- `homeTitle` contains `'Sterling'` in both locales.
- English `index` is `'index'`; Spanish `index` is `'índice'`.
- English `chooseLanguage` is `'Choose language'`; Spanish is `'Elegir idioma'`.

### Input

`locale: string` - any string; normalized internally via `normalizeLocale`

### Output

`UiLabels` object with all required keys populated.

---

## Edge cases

- `getUiLabels` called with `undefined` -> `normalizeLocale` handles it, returns English labels.
- `localeFromPathname('')` -> no segments, `normalizeLocale` returns `'en'`.
- `localeFromPathname('//')` -> no non-empty segments, returns `'en'`.
- Pathnames with query strings or hashes are not the expected input format;
  behavior is unspecified for those inputs.
